## How the templates work

- Each `.dc.html` opens directly in a browser — no build step. It loads `support.js` (rendering runtime) and `doc-page.js` (A4 pages, print) or `deck-stage.js` (slides). Keep these files next to the template; if you copy a template into `round-N/`, copy or relatively link the runtime files too (or change `src="./support.js"` to `src="../templates/support.js"`).
- The page content lives between `<x-dc>` and `</x-dc>`. Each A4 page is one `<section class="page" data-screen-label="NN Name">`. Each slide is one `<section data-label="…">`.
- **All styling is inline** (`style="…"`). There are no CSS classes. Copy an existing block to make a new one.
- The cover mountains are generated by the small class at the bottom of the file (`ridges`) — leave it.
- To get a PDF: open the file in Chrome → Print → Save as PDF, paper A4, margins "None", background graphics on. Pages are fixed-size: if text overflows a page it is cut off, so check every page.

## Each round — workflow

1. Update `data/holdings.json` for the new round. The daily workflow runs `scripts/update_portfolio.py` and writes `data/portfolio.json`.
2. Copy `templates/Report Template.dc.html` (or the previous round's report) to `reports/round-N/Round N Report.dc.html`.
3. Fill the numbers **from `data/portfolio.json`** (never type them by hand from memory). Mapping below.
4. Write the text (letter, outlook, rationale) from the team's notes / LaTeX. Replace every `[bracket]` placeholder and every `—` / `x.x%`.
5. Check every page for overflow, export `round-N.pdf` into `reports/round-N/`, commit.
6. The website links to `reports/round-N/` — keep that folder name.

Optional (better): instead of hand-filling, add a script `scripts/build_report.py` that reads `data/portfolio.json` and replaces values in the HTML (e.g. elements tagged with `data-field="metrics.ex_ante_vol"`). Then each round is: run script → write text → export.

## Field mapping (`data/portfolio.json` → report)

| Report element | JSON field | Format |
|---|---|---|
| NAV | `nav` | `USD 100.0M` |
| Total return | `metrics.total_return` | `+1.2%` |
| Realised volatility | `metrics.realised_vol` | `8.1%` |
| Ex-ante volatility | `metrics.ex_ante_vol` | `7.9%` |
| Sharpe | `metrics.sharpe` | `0.85` |
| Max drawdown | `metrics.max_drawdown` | `−3.4%` (use U+2212 minus) |
| 1-month 5% VaR | `metrics.var_1m_95_pct`, `metrics.var_1m_95_usd` | `3.8%` / `USD 3.8 million` |
| Risk model window | `metrics.risk_model_window` | `Oct 2021 – Sep 2026` |
| Holdings table (ticker, name, class, weight, risk contr.) | `holdings[].ticker/name/asset_class/weight/risk_contribution` | weights `12.5%` |
| Orders table (shares, price, amount) | `holdings[].shares/price/market_value` | `USD 12,345,678` |
| Leftover cash | `cash.market_value`, `cash.weight` | |
| Asset-class bars | `asset_classes[]` | bar `width:%` = weight / largest weight |
| NAV chart | `nav_series[]` (`date`, `round`, `index`) | polyline, see below |
| Round table | `rounds[]` (`return`, `start_date`, `end_date`, `status`) | |

Round rules: Round 1 has **no benchmark** — compare only with the 8% volatility target (range 7–9%). From Round 2, active return and tracking error are measured against the team's own SAA. Currency is **USD**. Do not reintroduce a benchmark in Round 1.

### Charts
Charts are inline SVG so they stay sharp in PDF. Line chart: `viewBox="0 0 600 220"`, x = `i / (n−1) × 600`, y = `220 − (v − min) / (max − min) × 220` with ~10% padding on min/max; fund line `stroke="#111111" stroke-width="2"`, reference line `stroke="#888888" stroke-dasharray="5 4"`, gridlines `stroke="#d8d3cc"`, labels Geist Mono 9px `#615e5b`. Alternatively make a PNG in Python (matplotlib) with the same colours and put it in `figures/`, then `<img src="../figures/x.png" style="width:100%">`.
